# Cleaning decisions

Every transformation applied to the raw UCI records, with the evidence behind it. Counts come
from `docs/DATA_AUDIT.md` (generated by `scripts/01_download_audit.py`), which recomputes
them from the downloaded files; the code is in `src/fedheart/data.py`.

## Source

* Files: `processed.cleveland.data`, `processed.hungarian.data`,
  `processed.switzerland.data`, `processed.va.data` from
  <https://archive.ics.uci.edu/ml/machine-learning-databases/heart-disease/>.
* Verified on retrieval: 14 comma-separated fields per record; 303 / 294 / 123 / 200 records
  (920 total); SHA-256 digests recorded in `configs/default.yaml`. A mismatch stops the
  pipeline.
* Each file is one hospital (client). Files are never merged and re-split into artificial
  clients. Record identifiers (`record_id = <hospital>_<row>`) are created for bookkeeping
  only and, like the hospital name, are never model inputs.

## Variables

The 13 standard predictors: age, sex, cp, trestbps, chol, fbs, restecg, thalach, exang,
oldpeak, slope, ca, thal. The target is derived from `num` (rule C6).

## Rules

| Rule | What | Where it applies | Decision | Why |
|---|---|---|---|---|
| C1 | `?` (and `-9`/`-9.0`, the code given in `heart-disease.names`) | all files; heavy in Hungary, Switzerland and VA (e.g. `ca` missing in 291/294, 118/123, 198/200 records) | set to missing | documented missing-value markers; the processed files actually use `?` |
| C2 | `chol == 0` | all 123 Switzerland records; 49 VA records | set to missing | 0 mg/dl serum cholesterol is impossible; the value encodes "not measured". Switzerland therefore has no observed cholesterol at all |
| C3 | `trestbps == 0` | 1 VA record | set to missing | a resting blood pressure of 0 mm Hg is impossible |
| C4 | `oldpeak < 0` | 11 Switzerland records, 1 VA record | **kept** | negative ST depression is clinically interpretable (ST elevation) and there is no documented error code; changing it would be a guess |
| C5 | categorical value outside the documented levels | none found | pipeline stops | protects the fixed one-hot schema |
| C6 | `num` 0–4 | all records | `target = 1` if `num` ≥ 1 else 0 | binary presence of disease, as specified |
| C7 | exact duplicate rows (all 14 raw fields identical) | Hungary rows 101 & 102; VA rows 139 & 187 | **kept**, linked by a duplicate-group id | no patient identifiers exist, so we cannot tell a data-entry repeat from two patients with identical measurements. Keeping both preserves the published record counts; the group id makes the splitter put both copies in the same partition, so a copy can never be in training while its twin is in validation or test |

Note on `num`: Cleveland, Switzerland and VA use the documented 0–4 coding, but the Hungary
file only contains 0 (188 records) and 1 (106 records). The binary target is unaffected, but
severity grades are not comparable across hospitals, which is one more reason to use the
binary outcome.

Other checks reported in the audit, which required no action: no record is identical across
hospitals; no duplicate has conflicting labels; all observed numeric values lie in broad
physiological ranges after C2/C3 (age 18–100, trestbps 60–250, chol 80–700, thalach 50–250,
oldpeak −3 to 7).

## What is *not* done here

* No imputation happens during cleaning. Missing values stay missing and are handled by the
  preprocessing step (training-data statistics only; see `docs/METHODS.md`).
* No record is removed. The analysis uses all 920 records.
* No outlier clipping or winsorizing.
